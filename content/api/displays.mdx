Displays are bound to your account through the Portal or the mobile app; the
SDK observes them, and can change which already-rendered frame a panel is
showing.

## `list()`

```ts
const page = await inklet.displays.list({ limit: 20 });
```

```ts
list(options?: ListDisplaysOptions): Promise<DisplayPage>
```

<SdkType file="displays" name="ListDisplaysOptions" />

Returns a cursor page:

<SdkType file="displays" name="DisplayPage" />

Paging through everything:

```ts
let cursor: string | undefined;
const all = [];

do {
  const page = await inklet.displays.list({ cursor, limit: 50 });
  all.push(...page.items);
  cursor = page.nextCursor ?? undefined;
} while (cursor);
```

A `limit` outside 1–50, or a non-integer, throws `ConfigurationError` locally.

## `retrieve()`

```ts
const display = await inklet.displays.retrieve("display_123");
```

Throws `NotFoundError` if the id is unknown, and `ConfigurationError` if the id
is not a non-empty string.

## `listQueue()`

What is waiting to go on the panel, oldest first within a priority, optionally
within a time range:

```ts
const queue = await inklet.displays.listQueue(display.id, {
  from: new Date("2026-08-01T00:00:00Z"),
  to: new Date(),
  limit: 20,
});
```

```ts
listQueue(displayId: string, options?: ListDisplayQueueOptions): Promise<DisplayQueuePage>
```

<SdkType file="displays" name="ListDisplayQueueOptions" />

`from` and `to` accept a `Date` or anything `new Date()` parses; both are sent
as ISO strings. An unparseable value, or `to` earlier than `from`, throws
`ConfigurationError`.

Each item:

<SdkType file="displays" name="DisplayQueueItem" />

<Callout>
  The queue only ever holds `queued` Presentations. Once one is delivered it
  leaves the queue, and the frame it replaces expires rather than going back in.
  For the display's full history — the `published`, `confirmed`, and `expired`
  ones too — use
  [`presentations.list({ displayId })`](/api/presentations#filtering-by-display).
</Callout>

## `current()`

The confirmed Presentation a display is showing, or `null`:

```ts
const current = await inklet.displays.current(display.id, { format: "png" });

if (current?.image) {
  console.log(current.image.url);
} else {
  console.log("nothing confirmed yet");
}
```

```ts
current(displayId: string, options?: { format?: "png" | "raw2" | "raw4" }): Promise<Presentation | null>
```

<Callout>
  `null` is a normal answer, not an error — a display that has never confirmed
  a frame has no current Presentation. Handle it before reading `.image`.
</Callout>

## Changing what is on the panel

Picking what a panel shows needs no AI and no new Content. Neither call below
consumes AI or push quota.

### `setCurrent()`

```ts
await inklet.displays.setCurrent(display.id, presentation.id);
```

```ts
setCurrent(displayId: string, presentationId: string, options?: CallOptions): Promise<Display>
```

The Presentation must be one of yours, of `kind: "display"`, already delivered
to **this** display, and finished rendering. An `expired` one can be
reactivated — that is how "go back to the previous image" works. Anything else
is a `ConflictError`:

| `details.reason` | Meaning |
| --- | --- |
| `targetless` | The Presentation has no target display, so it cannot go on a panel. |
| `not_delivered` | It was never delivered to any display. |
| `other_display` | It was delivered to a different panel. |
| `not_rendered` | It has no rendered image yet. |

<Callout type="warn">
  Branch on `error.details.reason`, not on `error.message`. The four reasons
  above are the stable part. The whole envelope is `409` with
  `code: "presentation_not_deliverable"` and
  `details: { displayId, reason, presentationId }`.
</Callout>

The frame that was on the panel becomes `expired`; it does not go back into the
queue. The switch lands on `pendingPresentationId`, and
`currentPresentationId` follows once the panel confirms — which for an offline
panel is its next sync.

### `advance()`

```ts
const { changed } = await inklet.displays.advance(display.id);
```

Rotates to the next queued Presentation, highest priority first and oldest
first within a priority. `changed: false` means the queue was empty, which is a
normal `200` and changes nothing — not an error. Otherwise the effect matches
`setCurrent()`.

Neither `setCurrent()` nor `advance()` is retried automatically. A retried
`advance()` after a lost response would skip a second Presentation, so after a
network error read the display and check `pendingPresentationId` before
calling it again.

### `waitUntilCurrent()`

```ts
await inklet.displays.waitUntilCurrent(display.id, presentation.id, {
  timeoutMs: 10 * 60_000,
});
```

Polls until the display reports `presentationId` as its **confirmed** current
Presentation. `pollIntervalMs` defaults to 1,000 ms and `timeoutMs` to
120,000 ms. Up to three failed reads in a row — a dropped connection, a
timeout, or HTTP 408, 429, or 5xx — are retried with back-off.

<Callout>
  A timeout throws `OperationTimeoutError` and does not cancel the switch — the
  panel still shows the Presentation once it syncs. `error.details` carries
  `displayId`, `presentationId`, `pendingPresentationId`, and `timeoutMs`.
</Callout>

## The `Display` type

<SdkType file="displays" name="Display" />

| Field | Notes |
| --- | --- |
| `name` / `nickname` | `name` is the bound device name; `nickname` is user-set and may be `null`. |
| `tags` | Free-form labels — a practical routing key for Manual pushes. |
| `online` | Whether the panel is currently reachable. |
| `syncIntervalMinutes` | How often it wakes to ask for work. |
| `nextSyncAt` | When to expect the next pickup. |
| `pendingPresentationId` | Handed over but not yet confirmed. |
